# PROJECT: Model Pilot MVP

당신은 시니어 풀스택 엔지니어이자 AI 시스템 아키텍트다.

내가 만들고 싶은 제품은 **Model Pilot**이다.

Model Pilot은 Claude Code 같은 AI Coding Agent를 사용할 때 사용자가 직접 어떤 AI 모델을 써야 할지 고민하지 않도록 돕는 **로컬 AI Resource Meter + Model Advisor**다.

최종 비전은 Claude, OpenAI, Gemini 등 여러 AI 모델을 자동으로 선택하고 라우팅하는 AI Orchestrator이지만, 이번 작업에서는 반드시 **MVP 1단계**에 집중한다.

---

# 1. 핵심 목표

Windows PC에서 Model Pilot을 실행하면 작은 로컬 프로그램이 실행되고, Claude Code를 사용하는 동안 다음 정보를 실시간으로 보여준다.

1. 현재 사용 중인 AI 모델
2. 현재 Context 사용량
3. Context 최대 크기
4. Context 사용률 %
5. 현재 세션 비용
6. 현재 작업 유형
7. 작업 난이도
8. 예상 추가 Token 사용량
9. 예상 완료 비용
10. 현재 모델 적합도
11. 추천 모델
12. 추천 이유
13. Context 위험 경고
14. 사용 기록

Model Pilot의 핵심 철학은 다음과 같다.

> 사람은 일을 지시한다.
> 어떤 모델을 쓸지, 얼마나 많은 토큰이 필요한지, 현재 모델이 적합한지는 Model Pilot이 판단한다.

# 3. MVP 범위

이번 버전에서는 AI 모델을 자동으로 변경하지 않는다.

즉:

AUTO ROUTING = OUT OF SCOPE

이번 MVP에서는 다음까지만 구현한다.

### Phase 1 — Meter

실제 상태 표시

### Phase 2 — Advisor

작업 난이도 및 모델 추천

### Phase 3 — Predictor

예상 Token / 예상 비용 계산

사용자가 Model Pilot의 추천을 보고 직접 모델을 변경하는 방식이다.

# 20. 모델 추천

초기 추천 정책:

LOW

저비용 / 빠른 모델 권장

MEDIUM

중간급 모델 권장

HIGH

고성능 모델 검토

VERY_HIGH

최상위 모델 검토

하지만 현재 모델이 충분하면 굳이 상위 모델을 추천하지 않는다.

가장 중요한 철학:

MOST EXPENSIVE MODEL ≠ BEST RECOMMENDATION

추천은 항상

QUALITY × COST × SPEED × CONTEXT

를 종합한다.

# 22. Model Stickiness

MVP에서는 자동 모델 switching은 하지 않는다.

하지만 향후 기능을 위해 다음 개념을 데이터 구조에 포함한다.

switchThreshold

기본값:

15

새 모델의 점수가 현재 모델보다 15점 이상 높을 때만 변경을 고려한다.

이것을 Model Stickiness라고 한다.

# 44. 작업 방식

먼저 전체 프로젝트 아키텍처를 설계한다.

그 다음 실제 파일을 생성한다.

문서만 작성하고 끝내지 않는다.

실제 실행 가능한 코드를 만든다.

모든 핵심 화면과 기능을 구현한다.

구현 도중 오류가 발생하면 직접 수정한다.

build / test / typecheck를 수행하여 오류를 해결한다.

작업 완료 시 다음을 보고한다.

1. 구현된 기능
2. 프로젝트 구조
3. 실행 방법
4. Claude Code 연결 방법
5. 아직 구현되지 않은 부분
6. 다음 개발 단계
7. 테스트 결과

**Model Pilot MVP가 Windows 로컬 PC에서 실제로 실행되어야 한다.**
